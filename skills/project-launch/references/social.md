# Social Posts

## Shape

The default audience is recruiters and non-technical readers. The article carries the detail, so the post only has to make them click.

- **LinkedIn**: two to four short lines. Line 1 is the hook in plain words ("I made my favorite 2000s MMORPG run in a browser with multiplayer."). Line 2 is the twist ("Not a remake. And AI agents wrote most of it."). Then a pointer and the link, which renders the article's card. No hashtag walls.
- **X**: a one-line hook, then a pointer emoji, with a native video attached. Put the link in the first reply, where it does not cost the post its reach.
- Check current platform guidance when unsure, for example reach of links and length. Date the sources, and treat contested advice as contested.
- Keep the post consistent with the article's framing: nothing the article withholds (names, possession of source code, official services), and no claim the article does not back.

## Approval and publishing

1. Write the drafts in a local file that is never committed to a public repository. Keep longer variants there too.
2. Show the user the exact text and the media. Send the video or images when the user is on another device.
3. Prepare each post in the user's logged-in browser up to the publish button, then wait for an approval that covers that post. "Publish both" covers both. A later edit to the text needs the user to see the new text.
4. Publish, open the post's own URL, add the link reply where the plan calls for one, and dismiss upsell dialogs without accepting anything.
5. When the article's title or description changes later, refresh the LinkedIn preview (see [publishing](publishing.md)).

## After posting

- The first hour matters: answer comments, and do not edit the post.
- Note questions about the code or requests for access. They are the signal for opening a closed-but-ready project.
