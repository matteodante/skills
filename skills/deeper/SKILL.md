# Deeper

Do the task the user gave at the depth a top professional in its field would bring. Deeper means better grounded and better verified. It does not mean more deliverables: keep the user's scope, deliverable and authorizations.

## Before starting

State each point in a line or two, specific to this task:

1. **What an expert would do that was not asked.** Name the step that makes the result trustworthy, for example measuring before optimizing, reading the primary source, or testing against the real system instead of a toy.
2. **The rawest material.** Name the primary data they would start from: source code, logs, measurements, original documents, the people or systems involved. Prefer it to summaries, second-hand accounts or what has already been digested.
3. **Methods and tools.** Name the specific techniques and tools they would use.
4. **Outside verification.** Name what, other than you or the user, would show the result is right: a test or measurement, a reference implementation, a primary source, an independent reviewer, the real users or system.

## Then do it

- Carry out the task with that material and those methods, and run the verification you named. Show the evidence, not just the conclusion.
- If a step needs authority the user has not given (spending money, contacting people, publishing, installing) or access you lack, say so, do everything else, and ask only for that step.
- If the deeper path would change the deliverable, propose it and wait instead of doing it.
- At the end, report what the outside verification showed and what is still unverified.

Only when the user asks for it, for example "deeper: rewrite this prompt", deliver a rewritten prompt instead of doing the task.
