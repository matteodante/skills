# Moonshot

Answer this for the thing the user names, called X below:

> What would be an absolute moonshot to improve X? Assume unlimited dev resources and 12 months. Use many tokens, be ambitious. Let it rip.

If X is unclear, take it from the current repository or conversation and say what you took. Ask only if there is nothing to go on.

This is a thinking deliverable. Do not start building, install anything or change files unless the user asks for that too. If the user wants it saved, write it to the file they name.

## Ground it first

Read the real thing before dreaming about it: the code, the product, the docs, the data, the users' complaints. In a few lines, state:

- what X is for and who it is for;
- where it is today, with the evidence you read;
- the ceiling: the constraint everyone treats as fixed (latency, cost, a manual step, a platform limit, a business model) that a moonshot should break.

## Then let it rip

Unlimited people and money are given; physics, the 12 months and the users' trust are not. Write long and go past the safe answer. Incremental items belong in the last section, not the vision.

1. **The moonshot in one paragraph.** What X is in 12 months, described as the user would experience it. It should sound slightly unreasonable.
2. **Why it changes the game.** The step change in numbers where possible (10x faster, zero manual steps, a new audience), and what becomes possible that was not before.
3. **The big bets.** Three to six pillars. For each: what it is, how it would actually work (architecture, models, data, algorithms, hardware, partnerships), why it is feasible now and what it unlocks.
4. **Wild ideas.** Ideas that may be too far even here. Flag them as such; one of them may be the real moonshot.
5. **The 12-month plan.** Quarter by quarter: teams, milestones and the demo that proves each quarter worked.
6. **What kills it.** The hardest technical, product and adoption risks, and the cheapest early experiment that would retire each one.
7. **What to do on Monday.** The moonshot-aligned steps that are worth doing with today's real resources, smallest first.

## Before handing off

- Every pillar must trace back to something you read in the grounding. Mark ideas that rest on assumptions you could not check.
- Say which parts are established technology and which are research bets.
- End with the one bet you would make if only one were allowed, and why.
